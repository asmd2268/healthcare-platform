# أساس المنصة المشترك

تم تنفيذ أساس Next.js/TypeScript داخل `apps/web` فقط، مع App Router وServer Components افتراضيًا. يوفر النواة: RTL/LTR، العربية الافتراضية والإنجليزية الكاملة، theme، Shell متجاوب، إعدادات علامة مركزية، عقود للهوية والصلاحيات والتدقيق وسير العمل والإشعارات والاستيراد/التصدير، وطبقة Supabase منفصلة للمتصفح وعميل خادم مستخدم مستقبلي RLS وعميل Admin-only معزول في `supabase-admin.server.ts`.

المصادقة عبر Supabase Auth، وفحص جلسة الخادم، وRLS ومخطط PostgreSQL الأساسي أصبحت متاحة للتطوير بمتغيرات البيئة الصحيحة. الإنتاج والتطوير يفشلان مغلقين إلى تسجيل الدخول عند غياب المصادقة أو إعداد Supabase؛ لا يوجد قبول لـcookie عشوائي. أصبح أساس التجهيز التجاري منفذًا بخيارات نشر كاملة أو محددة الوحدات، واشتراكات scoped، وحماية مسارات الوحدات من الخادم، وعلامة White Label موروثة حسب المنشأة والمنظمة والمرفق. لا يستبدل هذا الأساس الصلاحيات أو RLS، ولا يتضمن تحصيل المدفوعات أو الفوترة أو تحقق DNS الآلي أو رفع الشعارات. التراجع، الإشعارات الفعلية، الملفات، تنفيذ سير العمل والحذف الدائم ما زالت Contracts أو واجهات Placeholder وليست وظائف إنتاج.

راجع [White Label والترخيص](WHITE_LABEL_AND_LICENSING.md) للحزم الجاهزة، قواعد التفعيل، التراجع، ونطاق التكامل التجاري المؤجل.

إدارة النماذج الشاملة، والبيانات المرجعية، وإدارة سجلات قاعدة البيانات ليست ضمن وحدة التفتيش؛ ستنفذ في PR مستقل للمنصة المشتركة.
